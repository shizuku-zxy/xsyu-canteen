# 菜品标签标注终稿（2026-11，按楼层分工）

## 背景
用户反馈「想吃馒头」出来的是肉夹馍/炒馕、想喝「稀饭」出来的却是「米饭」。
根因：旧标签太粗（馒头/馍都糊成「小吃饼类」）、旧 NLU 把「稀饭」里的「饭」当成「米饭」。
2026-11 重构后：每道菜按食谱语义打**尽量多且准确**的标签（品类+细分+同义叫法+主料+口味+做法+特点），
查询时「菜名直接命中」优先，反义词（稀饭/米饭）自动排除。

## 本目录文件
`东食堂-一楼.json` / `东食堂-二楼.json` / `东食堂-三楼.json` /
`西食堂-一楼.json` / `西食堂-二楼.json` / `小吃街-street.json`

格式（每个楼层一个终稿，覆盖该楼层全部 dish_id）：
```json
{
  "floor": "东食堂-一楼",
  "tags": {"D0001": ["面", "面条", "油泼面", "面食", "主食", "辣"]},
  "new_tags": {"炸酱面": "细分"},
  "notes": "复核说明"
}
```

## 生产流程（可重放）
1. `services/lexicon.py` 是标签词库（细分家族/同义词/反义词/菜名规则），也是唯一口径
2. `python projects/03_服务端/tag_dishes.py --baseline-dir _work/tags_baseline`
   生成全库基线（机器按菜名规则打标）
3. 6 个楼层子代理分别复核本楼层基线：补同义标签、拆套餐/拼盘、修正误标（面馆小菜不串「面」、
   素臊子不带猪肉、米饭/粥不串味）、补主料口味做法 → 产出本目录 6 个终稿
4. `python projects/03_服务端/tag_dishes.py --merge-dir projects/03_服务端/tagging --apply`
   合并终稿 → 写 `dish.tags_str` + `tag` 表 + 重建 `dish_fts` + 刷新 128 个档口的统计
5. `python projects/03_服务端/export_tree.py --apply`
   把 DB 数据重新生成到 `02_前端/index.html` 的内联 TREE（前端浏览/搜索/筛选的数据源）
6. `python projects/03_服务端/selftest_queries.py` 回归自测（64 项）

## 标注要点（复核时遵循）
- 馒头类：`馒头` + `馍` + `白馍`；粥类：`粥` + `稀饭`；米线/米粉 → +`粉`；
  面 → `面`+`面条`+`面食`；米饭 → +`主食`；饺子/包子/馄饨 → +`水饺包子`+`面食`；
  夹馍 → +`馍`+`饼`；汤面/拌面/炒面/焖面等具体做法各打各的
- 套餐/拼盘要拆开打（如三秦套餐 → 凉皮+夹馍+馍+饼+汽水+套餐+快餐）
- 有肉/海鲜 → 主料 + `荤菜`（蛋不算荤菜）；素食只在确认无肉无海鲜无蛋时打
- 口味/做法看菜名与常识（红油→辣、糖醋→甜、锅包肉→炸、砂锅→焖炖…）
- 拿不准的不打；不打「素食」到肉菜上、不打「米饭」到面/粥上、不把面馆小菜标「面」
- 允许新增具体食物标签（写进 `new_tags`，维度只能是 品类/细分/特点/主料/口味/做法）

## 重放注意
- 若之后 `services/lexicon.py` 又有标签增删，建议先重跑基线、再复核受影响楼层，最后 merge + export_tree
- `tag_dishes.py --merge-dir` 只覆盖终稿里出现的 dish_id；DB 新增菜品若不在终稿里，会自动用 lexicon 基线兜底
